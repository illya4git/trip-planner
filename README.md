# Планувальник подорожей

Навчальний застосунок курсу «Програмування веб-застосувань» (ФІОТ КПІ, варіант 10): список подорожей,
маршрут кожної подорожі з міні-картою на Canvas і довідка про країни з локального API.
Клієнтська частина — HTML, CSS, JavaScript і Vue 3 з CDN, дані зберігаються в IndexedDB браузера,
сервер довідки — Node.js + Express (тека `server/`).

## Запуск

```bash
cd server
npm install
npm start
```

Застосунок відкривається за адресою http://localhost:3000.

## Безпека (практикум 15)

Аудит охоплює весь код практикумів 1–14: `index.html`, `js/app.js`, `server/server.js`.

### XSS

| Місце | Дані | Стан до аудиту | Рішення |
|---|---|---|---|
| Нотатки зупинки `{{ stop.notes }}` (маршрут і сторінка зупинки) | вільний текст користувача | безпечно: інтерполяція Vue записує значення як текст | залишено, додано коментар-попередження проти `v-html` |
| Назви подорожей, міст і країн у шаблонах Vue | введення користувача | безпечно: інтерполяція `{{ }}` | без змін |
| Картки країн `createCountryCard` | відповідь API | безпечно: `createElement` + `textContent` | без змін |
| Адреса на сторінці 404 | адресний рядок | безпечно: `textContent` | без змін |
| Підписи міні-карти | назви міст | безпечно: Canvas `fillText` не розбирає HTML | без змін |
| `renderList`, `clearView` | `innerHTML = ''` (без даних) | безпечно | замінено на `replaceChildren()` — у коді більше немає `innerHTML` |

Тестовий рядок `<img src=x onerror="alert('XSS')">` у полі нотаток відображається як текст, `alert` не з'являється.
Додатковий захист — заголовок Content-Security-Policy (див. нижче): навіть якщо колись з'явиться
вставка HTML через `innerHTML` чи `v-html`, браузер не виконає вбудований обробник `onerror`.

### Сторонній скрипт (Vue з CDN)

Було: `https://unpkg.com/vue@3/dist/vue.global.js` — «остання 3.x» без перевірки вмісту. Під час
аудиту цей тег уже віддавав версію, опубліковану того ж дня. Скрипт із CDN має повний доступ до сторінки
й до IndexedDB, тож будь-яка підміна на CDN виконалася б як власний код застосунку.

Стало: точна версія `vue@3.5.43`, production-збірка, атрибути `integrity` (SHA-384) і `crossorigin`.
Якщо CDN поверне змінений файл, браузер відмовиться його виконувати.

### Заголовки сервера

- `Content-Security-Policy` — скрипти лише з власного origin і unpkg.com, без вбудованих обробників;
  зображення — власні й flagcdn.com; `fetch` — лише власний API; заборона вбудовування в `<iframe>`.
  `'unsafe-eval'` — вимушений виняток: Vue з CDN компілює шаблони в браузері через `new Function`.
  Позбутися його можна лише переходом на збірку з попередньо скомпільованими шаблонами (Vite + npm).
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- Вимкнено `X-Powered-By: Express`.

### localStorage та IndexedDB

- **IndexedDB `TripPlannerDB`**: подорожі (напрямок, дні, бюджет, статус) і зупинки (країна, місто,
  дати, нотатки). Паролів, токенів і платіжних даних застосунок не зберігає. Єдине поле з потенційно
  чутливим вмістом — нотатки: користувач може записати туди номер паспорта чи код бронювання. Під полем
  додано підказку, що нотатки не шифруються і їх не варто використовувати для документів.
- **localStorage**: після практикуму 11 тут лишалася «резервна копія» маршруту `tripStops` разом
  із нотатками. Зміни й видалення в застосунку її не торкалися, тож видалена нотатка назавжди лишалася
  у відкритому вигляді. Тепер запис видаляється після міграції; лишається лише прапорець
  `tripStopsMigrated`.

### Секрети

У клієнтському й серверному коді немає ключів API, паролів чи токенів. Довідка про країни працює
з локальним файлом `server/data/countries.json`, ключ доступу не потрібен. `node_modules/` не потрапляє в Git.

### HTTPS

На `localhost` застосунок працює через HTTP — браузери вважають його безпечним контекстом.
Для публікації потрібен хостинг із HTTPS за замовчуванням.
